# BUG-2026-09-18-002

## Contract and reproduction

While editing a local note, update storage from another extension surface. Previously, normalized records acquired new object identities, so the editor's object comparison hid the draft. A delayed save could also close an editor opened subsequently, and one shared busy key failed to track concurrent operations on different records.

The local library must retain draft text across refreshes, match rows by URL/time, close only the unchanged editor that submitted a successful save, reject duplicate pending operations on the same record, and ignore stale reads. No build, application launch, deployment, schema change, or dependency change is authorized by this repair.

## Implementation

- Stable URL/time matching and explicit edit sessions protect editor lifecycle.
- A per-record pending set guards repeated submissions while allowing independent records.
- Save acknowledgement must explicitly report success. Text typed while a save is pending stays in the editor.
- Storage reads use a monotonic version and an unmount guard. Recovered reads clear their own error without concealing mutation errors.
- An externally deleted record keeps its draft visible with localized explanatory text and a disabled save action, allowing the user to copy the draft before canceling.
- Tab-opening failures are caught and reported through the existing error surface.

## Evidence and limitations

On 2026-09-18, `node --test scripts/local-library.test.mjs` passed all six tests: refreshed/deleted drafts, load-error recovery, delayed saves and ongoing typing, independent/duplicate mutations and missing acknowledgement, cancel/reopen of the same record, out-of-order reads and unmount. The harness executes the component's TypeScript logic with real Vue reactivity and mocked browser APIs; it does not render DOM or run Chrome.

`node node_modules/vue-tsc/bin/vue-tsc.js --noEmit` and targeted ESLint on the component and localization passed. No build or application launch was run during the original repair.

On 2026-09-23, the operator manually validated the local-library scenarios in the extension: draft retention, rapid updates, separate records, deletion/cancellation, and reload. This closes the rendered-browser validation gap. No build or application launch was run for this commit; the validation reflects operator confirmation and was not independently repeated in this session.
