# Bug Record: BUG-2026-05-24-008

## Summary

- Title: ReplayGlowz YouTube connect blocked or misdetected before Google OAuth
- Current status: `fixed-pending-verify`
- Severity: `high`
- Owner: Diane
- Next command: Retest ReplayGlowz production YouTube Connect with a signed-in browser session.

## Reproduction

- Preconditions:
  - User is signed into ReplayGlowz through suite Clerk identity.
  - WinFlowz entitlement bridge recognizes the Clerk account.
  - No active `replayglowz` or legacy `tubeflow` entitlement exists yet.
- Steps:
  1. Open ReplayGlowz production.
  2. Attempt YouTube Connect.
  3. Let ReplayGlowz call the WinFlowz entitlement bridge before Google OAuth.

## Expected Behavior

- A recognized Clerk account entering ReplayGlowz gets product-scoped `replayglowz/free` access by default.
- YouTube Connect can continue to Google OAuth once session and product-scoped free access are verified.

## Observed Behavior

- The account is recognized but ReplayGlowz access is inactive.
- YouTube Connect is blocked before Google OAuth with a missing/inactive entitlement message.
- After entitlement was fixed, ReplayGlowz can treat a stale `youtubeConnected` flag as connected even when usable YouTube tokens are missing, so it offers sync instead of the Google connection CTA.
- After stale YouTube state was fixed, OAuth start reaches ReplayGlowz Vercel API, but the cross-app WinFlowz entitlement verifier rejects the Clerk token with HTTP 401.
- After session verification was fixed, Google OAuth reaches the provider but rejects the YouTube callback because ReplayGlowz Vercel still uses a legacy TubeFlow OAuth client under ambiguous `GOOGLE_CLIENT_*` names.

## Evidence

- User-facing message: "Your account is recognized, but ReplayGlowz access is inactive."
- User-facing state after build `6ecfef2`: the app does not offer YouTube connection and `youtube:fetchYoutubePlaylists` fails server-side.
- User-facing error after build `f89af74`: "YouTube OAuth start failed (401): {\"error\":\"ReplayGlowz session verification failed.\"}"
- Vercel runtime logs on `www.winflowz.com` at 2026-05-24 19:54-19:55 UTC show `POST /api/bridge/entitlement` with `Clerk entitlement token verification failed.`
- Production env inspection showed the YouTube OAuth client ID came from `GOOGLE_CLIENT_ID`, which is ambiguous with Clerk/normal Google sign-in and points to the old TubeFlow client.
- ReplayGlowz server handler denies `missing_product_entitlement` with HTTP 403.
- WinFlowz bridge resolver returned `missing_product_entitlement` when no active product entitlement existed.
