# Bug Record: BUG-2026-09-18-003

## Reproduction and expected behavior

Source review found the bookmark menu mounted under body even when the player is fullscreen, always positioned below its trigger, and offering a controller action with an empty handler. It should stay inside the active fullscreen surface, remain within the viewport, and expose only working actions.

During Alt scrubbing, changing the URL or source on a reused video element caused release to restore the previous video's muted state. Alt scrubbing may mute temporarily, but must never pause or start playback: the video and YouTube progress bar continue moving while seeks are applied. Release restores the prior mute state only for the original connected video identity and source.

Opening the local/cloud app from the content script called the unavailable tabs API. Content now sends `rg:openApp` to the worker with a validated route, video ID and finite timestamp; async failure is shown only in the originating navigation generation. Worker-side validation is owned by the accompanying app-opening repair.

## Repair

The menu mounts inside the fullscreen element when present, flips above its trigger when necessary, clamps width/height and position, and closes on fullscreen, resize, outside scroll, Escape or lifecycle abort. The inert controller item is removed. Scrubbing no longer pauses or resumes the video; it mutes temporarily and release restores mute only when the connected video identity and source still match. Existing unrelated local content-script edits are preserved.

## Evidence and limitations

`node --test scripts/youtube-controls.test.mjs`: 3 passing behavioral tests evaluating production source. Cases cover both app routes, async errors and stale responses; fullscreen remount, positioning, tiny viewport constraints and abort; unchanged, replaced, navigated and detached media, initial pause, and repeated release.

`youtube-menu-browser.mjs` also passed in headless Chromium 1243 using the current content source and stylesheet directly, without packaging. The fixture checks actual fullscreen entry/exit and containment, menu bounding rectangles, both app-action clicks, a 180x120 viewport, and lifecycle abort. This is browser fixture proof; no real YouTube or installed extension verification is claimed. Runtime and worker errors use the localized generic app-opening failure text.

No build, app/server launch or commit was performed. Status remains fix-attempted pending human visual acceptance and real YouTube verification.
