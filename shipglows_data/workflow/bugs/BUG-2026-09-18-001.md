# Bug Record: BUG-2026-09-18-001

## Summary

Direct bounded repair, authorized by the operator's request to correct the reviewed extension defects. The content script previously called `chrome.tabs.create`, which belongs in an extension context. The worker now owns tab creation via `rg:openApp`. No new permissions, dependency, build or deployment.

## Reproduction

On a YouTube watch page, choose the local or cloud app action in the extension menu. Source inspection establishes the unsupported direct API call; no browser reproduction is claimed in this run.

## Expected Behavior

Open the internal watch/play route with the current video and finite nonnegative timestamp. Invalid requests must not open a tab; opening failures must produce a failure response.

## Observed Behavior

The previous content-script call required an unavailable API and could not open the app. The bookmark worker also responds to unknown non-`rg:` messages, requiring a namespaced action to prevent competing responses.

## Evidence

`ext/scripts/app-navigation.test.mjs` exercises the actual transpiled navigation worker and existing listener dispatch. Five tests pass: both routes, timestamp zero/rounding, validation and sender rejection, extension pages including tabs, tab-creation failure, and coexistence with bookmark/playback handlers.
