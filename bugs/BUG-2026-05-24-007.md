# Bug Record: BUG-2026-05-24-007

## Summary

- Title: Browser privacy blocking leaves app as a blank page
- Current status: `fixed-pending-verify`
- Severity: `medium`
- Owner: Diane
- Next command: `/sf-prod app.replayglowz.com after deploy`

## Reproduction

- Preconditions:
  - Use a browser/privacy setup that blocks scripts or requests needed by the app, such as Vivaldi tracker blocking.
- Steps:
  1. Open `https://app.replayglowz.com/`.
  2. Keep browser blocking enabled.
  3. Observe the app startup surface.

## Expected Behavior

- The user should see a static fallback explaining that ReplayGlowz could not finish loading and that browser privacy blocking may need to be disabled for the app domains.

## Observed Behavior

- The user saw a blank page with no redirect and no visible instruction.
- Disabling Vivaldi blocking activated the page.

## Evidence

- Operator report: Vivaldi blocking caused the blank page; selecting no blocking made the app load.
- `curl` evidence from the previous diagnosis showed `https://app.replayglowz.com/` served `index.html` with script assets, so the blank surface was client/runtime-side rather than an HTTP redirect.
