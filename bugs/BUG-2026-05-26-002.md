# Bug Record: BUG-2026-05-26-002

## Summary

- Title: Playlists onboarding and create button do not match intended low-friction UX
- Current status: `fixed-pending-verify`
- Severity: `medium`
- Owner: Diane
- Next command: `/sf-ship replayglowz-youtube-parity-stabilization-qa-closure`

## Reproduction

- Preconditions:
  - Production app with authenticated test account.
  - Imported playlist `Fun` exists.
- Steps:
  1. Open ReplayGlowz.
  2. Click Playlists in the sidebar.
  3. Observe the onboarding banner and bottom-right `+`.
  4. Click `+`.

## Expected Behavior

- Onboarding should be contextual and not tell the user to create a playlist first when an imported playlist already exists.
- The create playlist affordance should remain subtle and ideally appear only in the intended scroll/fade state.
- The create/edit flow should match the expected popup/lightweight interaction if that is still the product direction.

## Observed Behavior

- Banner says: "Create one playlist first, then refresh to import new YouTube changes." This is stale or misleading when the user already has imported playlist `Fun`.
- Bottom-right `+` is visible at the top of the page even before scrolling.
- Clicking `+` opens a full `Create Playlist` page.
