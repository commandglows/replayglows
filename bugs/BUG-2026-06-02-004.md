# Bug Record: BUG-2026-06-02-004

## Summary

- Title: Play advanced actions depend on fragile current-video readiness
- Current status: `fixed-pending-verify`
- Severity: `medium`
- Owner: Diane
- Next command: `/sf-test --retest BUG-2026-06-02-004`

## Reproduction

- Preconditions:
  - A signed-in user is on the Play page with a route `videoId`.
  - The video may have just been opened from Feed, a YouTube playlist, a ReplayGlowz feed, or selected through Next/Previous.
- Steps:
  1. Open the advanced Play bottom controls.
  2. Tap `Channel`.
  3. Use the speed controls immediately after arriving on Play.

## Expected Behavior

- `Channel` opens the feed picker when the current video's channel metadata is already known from the source queue, even if Play page video providers are still loading.
- `Channel` never uses stale channel metadata from the previous video after Next/Previous.
- Speed controls update consistently and apply once the player is ready.

## Observed Behavior

- `Channel` can still block on current video metadata even when the playback session was started from a feed/playlist item that already had channel metadata.
- Speed controls can be tapped before the iframe/player is ready and be ignored.

## Evidence

- User report in chat on 2026-06-02.
- Static inspection showed `PlaybackQueueItem` did not carry `youtubeChannelId` or `channelTitle`.
- Static inspection showed Play channel-to-feed resolution only used `_latestCurrentVideo` or `videoByYoutubeIdProvider`.
- Static inspection showed speed changes returned early when `_isPlayerReady` was false.
