# Bug Record: BUG-2026-05-26-003

## Summary

- Title: Possible hidden YouTube quota usage during navigation
- Current status: `fix-attempted`
- Severity: `medium`
- Owner: Diane
- Next command: `/sf-ship replayglowz-youtube-parity-stabilization-qa-closure`

## Reproduction

- Preconditions:
  - Production app with authenticated test account.
  - Imported playlist already exists.
  - No explicit sync/import/refresh should be clicked.
- Steps:
  1. Observe quota at the top of the app.
  2. Navigate through Videos, Playlists, Play, Preferences and Notes.
  3. Do not trigger refresh, sync, import, or YouTube connect.
  4. Observe whether quota changes.

## Expected Behavior

- Cache-first navigation should not spend YouTube quota.
- Quota should only change after a deliberate YouTube API action or a clearly documented post-connection sync.

## Observed Behavior

- The visible quota counter was `9 / 1000` after playlist URL import.
- Later navigation screenshots show `10 / 1000` without an intentional sync/import action during that QA pass.
- Convex log sampling did not return enough history to confirm the exact action.
