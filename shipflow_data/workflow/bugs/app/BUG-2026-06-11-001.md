# Bug Record: BUG-2026-06-11-001

## Summary

- Title: Android Google Sign-In fails with ApiException 10 after bootstrap
- Current status: `fix-attempted`
- Severity: `high`
- Owner: Diane
- Next command: register the stable debug APK SHA fingerprints in Firebase/Google, run Android CI, and retest the uploaded artifact

## Reproduction

- Preconditions:
  - Install Android debug APK produced by GitHub Actions run `27305689222`.
  - Open ReplayGlowz on Android.
- Steps:
  1. Reach the sign-in screen.
  2. Start Google Sign-In.
  3. Observe the sign-in failure.

## Expected Behavior

- Android Google Sign-In uses Firebase native auth.
- Google Sign-In returns an ID token.
- Firebase Auth accepts the Google credential and session bridge resolution can continue.

## Observed Behavior

- The app reaches auth after bootstrap.
- Google Sign-In fails with `PlatformException(sign_in_failed, com.google.android.gms.common.api.ApiException: 10)`.
- UI reports `Auth unavailable: ReplayGlowz sign-in failed`.

## Evidence

- User report on 2026-06-11: `Sign-in failed: PlatformException(sign_in_failed, com.google.android.gms.common.api.ApiException: 10: , null, null)`.
- Local plugin source for `google_sign_in_android 6.2.1` states Android apps are identified by package name plus SHA-1 signing key, and `clientId` is not supported on Android.

GitHub Actions had no stable checked-in debug keystore, so the debug APK fingerprint was not durable. | supported |
